Openmd 全景

粘贴一个链接，把原文或逐字稿存成 Markdown。不总结、不改写。下面是它内部怎么走，以及每个平台目前靠哪些工具拿到内容。数据取自 routing/routes.json 和工具卡，2026-11-08。

架构

两个入口，一条主流程。插件只是把链接交给本机宿主排队，真正干活的还是同一个 openmd go，所以终端和插件结果一致。

路线是数据，不是代码。换工具、调顺序只改 routes.json 和工具卡；每个工具在独立子进程里跑，坏一个不影响其他。

默认不打扰。日常使用不确认、不弹窗；云服务、批量全量抓取、账号写操作永远要你明确开启。

“需要”里的权限：日常使用（终端 / 插件）会按路线自动开启公网、浏览器、下载、转写；账号登录和云服务不会自动开启。“部分可用”是项目自己的保守口径：已有真实样本跑通，但没覆盖该平台所有内容形态。

主要外部工具

opencli浏览器桥接：用你已登录的 Chrome 读字幕、逐字稿、正文（YouTube、B站、小宇宙、小鹅通、公众号、X…）。后台窗口已改为最小化。
yt-dlp下载 YouTube / B站 / X 的音视频，供本机转写；只存临时目录。
本机 ASRasr.auto 自动选已就绪的 CUDA worker（Qwen3-ASR / faster-whisper）；模型不自动下载。
yutto · xyz-dlB站、小宇宙的专用下载器，走“整段媒体 + 转写”路线。
youtube-transcript-api不开浏览器直接取 YouTube 字幕。
defuddle · trafilatura网页和公众号正文抽取，去掉导航和广告。
x-tweet-fetcherX 帖子正文与长文（Article），不需要登录。
lark-cli飞书文档导出，需要你的飞书登录。
markitdown · docling · OCRPDF、Office、截图转文字；OCR 用 RapidOCR / PaddleOCR / Tesseract 依次兜底。
