## [0.2.2]
### 修复 / Fixed
- 原生文字 PDF（如论文）不再因为排版细节整页丢失：文字层改为逐字核查，不可见文字（不可见渲染、透明、低对比、极小字号、页外、被裁掉、被遮盖、隐藏图层）逐字删除，连字、字距等有歧义的排版保留文字并标为“文字层未核验”。未授权 OCR 时，10 篇冻结论文的文字召回由 0.16 提高到 0.995；回执写为“已输出 N/N 页，其中 M 页文字层未核验”。 / Native-text PDFs such as papers no longer lose whole pages to layout details: the text layer is checked per glyph, invisible text (invisible render mode, transparent, low contrast, tiny, off-page, clipped out, covered, hidden layers) is removed character by character, and ambiguous layout such as ligatures and kerning keeps its text marked “text layer unverified”. Without OCR permission, text recall on 10 frozen papers rose from 0.16 to 0.995, and the receipt reads “output N/N pages, M with an unverified text layer”.
- 网页文章不再静默截断：同时比较 Defuddle 与 trafilatura 的结果，主结果只截到页面正文一小部分时换用更完整的候选，仍截不全时标为 partial 并在回执中写明覆盖情况（例如 RFC 9110 由约 9 KB 片段恢复为完整正文）。 / Web articles are no longer silently truncated: Defuddle and trafilatura results are compared, a more complete candidate replaces a primary result that covers only a small part of the page, and a page that still cannot be captured fully is marked partial with coverage in the receipt (for example, RFC 9110 now comes out whole instead of a ~9 KB fragment).
- 更多错误页与失效链接被拒收（软 404、挑战页外壳、Not Found、示例域名、公众号“参数错误/内容不存在”状态页），引用这些短语的正常文章仍然保留。 / More error pages and dead links are refused (soft 404s, challenge-page shells, Not Found, example domains, WeChat “参数错误/内容不存在” status screens), while articles that quote those phrases are kept.
### 新增 / Added
- 小宇宙单集在逐字稿前附上页面上的节目标题与简介。 / Xiaoyuzhou episodes include the page's episode title and show notes before the transcript.
- 可选 MinerU 引擎：自行安装 MinerU 后，用 `--ocr-engine mineru`（MCP 同名参数）把扫描 PDF 与图片交给它识别；在 `tools.mineru.executable` 或 `OPENMD_MINERU` 指定位置，`tools.mineru.tier` 选 basic / standard；未安装时明确报错并给出下一步，不加参数时行为不变。Openmd 不打包、不分发 MinerU 及其模型，使用时请遵守其许可。 / Optional MinerU engine: after installing MinerU yourself, `--ocr-engine mineru` (same MCP parameter) sends scanned PDFs and images to it; set its location with `tools.mineru.executable` or `OPENMD_MINERU` and pick `tools.mineru.tier` basic / standard. A missing install fails with a clear next step, and nothing changes without the flag. Openmd neither bundles nor redistributes MinerU or its models; follow its license when you use it.
- CONTRIBUTING 改为中英双语，补充托管 OpenCLI、生成文件规则，并新增浏览器扩展 macOS / Linux 移植指南。 / CONTRIBUTING is now bilingual, covers the managed OpenCLI and generated-file rules, and links a new macOS / Linux browser-extension porting guide.

## [0.2.1]
### 新增 / Added
- 右键转 Markdown 的菜单项使用 Openmd 仓鼠图标；进度窗口改为品牌暖色样式，显示当前文件与进度条，结束后按类别汇总结果并列出失败原因，可直接打开结果文件夹，全部成功时自动关闭。 / The right-click “Convert to Markdown” entry uses the Openmd hamster icon; the progress window adopts the warm brand style with the current file and a progress bar, then summarizes results by category, lists failure reasons, opens the result folder, and closes itself when everything succeeded.
- 问题报告覆盖更多情况：链接路线失败的任务也能生成只含回执的脱敏包；开启问题包后，看似成功但结果不对的已加载页面任务可在扩展弹出页的最近任务中手动生成报告；脱敏时保留由 ASCII 字母组成的页面结构名，其余 id 仍做哈希。 / Feedback packages cover more cases: failed link-route tasks produce a receipt-only sanitized package; with packages enabled, a loaded-page task that looked successful but came out wrong can be reported from the recent tasks in the extension popup; sanitizing keeps ASCII-letter structural ids and still hashes all other ids.
### 修复 / Fixed
- 从信息流打开的小红书笔记（弹窗）只读取当前打开的笔记，不再误用背后卡片的标题和作者，也不再混入评论、头像和按钮文字；页面上的笔记与请求的不一致时拒收。 / A Xiaohongshu note opened from the feed (as a modal) is read on its own: no title or author from the cards behind it, no comments, avatars or button labels; a page whose note differs from the requested one is rejected.
- 抖音等对 HEAD 请求返回 404 的页面不再被误判为“页面不存在”，改为再用 GET 确认。 / Pages such as Douyin that answer HEAD with 404 are no longer refused as missing; a GET now confirms first.
- 问题报告失败时显示真实原因和下一步，不再一律提示“去设置里开启”。 / A failed feedback report now shows the actual reason and next step instead of always pointing to the settings.
