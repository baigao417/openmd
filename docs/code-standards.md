# Code Standards

硬规则。每条都来自 [LESSONS.md](../LESSONS.md) 中在 3 个不同日期重复出现的教训，或项目创立时就确定的产品合同。PR 评审按这里逐条检查。新增规则必须注明来源。

## 产品合同（创立即确定）

- **CS-1 原文优先**：默认输出是原始正文 / 逐字稿。不总结、不改写、不润色、不补标点。可读化交给下游工具。
- **CS-2 状态诚实**：`status`（verified / partial / failed）描述结果是否可用，`source_level`（native_text / native_caption / auto_caption / media_asr …）描述正文来自哪里，两者不能混用。拿不全就标 `partial` 并写明缺什么，不能报成 `verified`。
- **CS-3 权限默认**：给了保存目录（或在终端交互）即自动开启公开网络读取、浏览器读取、媒体下载、本机转录。**云服务永远不默认开启**。显式传入的能力开关只能收窄权限。
- **CS-4 凭证不落盘**：密钥只走环境变量；cookie、token、登录态不得进入仓库、runlog、Markdown 产物或测试 fixture。
- **CS-5 发现与提取分离**：合集 / 作者主页的 discovery 和逐条 extraction 分开；`--manifest-only` 不触发正文提取。

## 验证规则

- **CS-6 真实验证**：可用性结论只来自真实链接跑真实 CLI 并读实际产物；mock / fixture 只防回归。PR 必须写"没验证什么"。
- **CS-7 先红后绿**：bug 修复必须附带一个修复前会失败的测试。

## 晋升自 LESSONS 的规则

- **CS-8 拒收平台状态页**（来源：LESSONS 2026-11-11、2026-11-15；第 3 次出现即正式生效，目前为预备规则）：平台接入必须附带该平台"已删除 / 不存在 / 需验证"状态页的拒收测试。
- **CS-9 验证环境即使用环境**（来源：LESSONS 2026-11-15、2026-11-17、2026-11-19，第 3 次出现已生效）：验收必须写明结果在哪个环境被谁消费，并在那个环境里跑一次：装好依赖的 checkout、安装后的 wheel、已注册的浏览器宿主与扩展副本。core 测试默认隔离外部插件；迁移运行时或工具位置时，同时检查仓库外的注册使用方（如 native host）；可选依赖导致的 skip 必须写明，并在装了依赖的环境中补跑。
